# ClipMD 详细说明

> 这份是 **macOS 版**的说明。Windows 版（Rust 写的，功能一样）见 [windows/README.md](../windows/README.md)。

复制 AI 的回复后按 **⌃⌥S**：内容存成 `.md` 文件，同时把这个文件放到剪贴板。到微信、飞书、邮件里 ⌘V，发出去的就是文件附件。

也能截图（**⌃⌥A**）：自动认出窗口、放大镜取色、画矩形椭圆、打马赛克、钉在桌面，或者截图后直接识别里面的文字（**⌃⌥O**），文字放进剪贴板。三个快捷键都可以在设置里改。

macOS 26 及以上，Swift 6 + SwiftUI（界面、Liquid Glass、动效）+ AppKit（窗口行为、剪贴板、拖拽）。唯一的第三方代码是用来画公式的 SwiftMath（MIT），以源码形式放在 `Vendor/` 里，见下面的「公式」。

## 用法

- **保存**：点悬浮窗里的「保存为 Markdown」，或者按 **⌃⌥S**。文字存成 md 后，文件会放回剪贴板。成功时屏幕顶部会弹出「已保存为 Markdown」，按钮也会短暂变成绿色；失败时悬浮窗里会写明原因，需要改设置的会附一个按钮直接跳过去
- **连点两次复制**：同一段文字 3 秒内复制两次（连按两次 ⌘C，或者把「复制」按钮点两下），就会直接保存，不用再按快捷键。3 秒是为了照顾复制后会卡一下的网页；要求两次内容相同，所以不容易误触。如果系统没有设成「始终允许」读取剪贴板，就只能看次数，要在 0.6 秒内连点两次。因为是自动触发的，保存后悬浮窗里会出现「撤销」：点了会把文件移到废纸篓，并把原来的文字放回剪贴板。连点复制的如果不是文字（比如在 Finder 里复制文件），会被安静地忽略
- **复制后的提示**：每复制一段文字，悬浮窗里的保存按钮会弹一下，显示「刚复制了一段文字，点这里存成 md」，5 秒后恢复。有些网页的复制按钮点一次后会进入「已复制」状态、几秒内再点不会复制，这时连点两次没用，就点一下复制，再点一下这个按钮
- 上面两项在设置里一起开关：「监听复制」
- **网页内容转 Markdown**：在网页上选中一段再复制，纯文本会丢掉格式，所以 ClipMD 会读剪贴板里的网页格式（HTML），转成 Markdown 再存：标题、有序/无序列表（含嵌套）、代码块（带语言）、行内代码、粗体斜体删除线、链接、图片、引用、表格、任务列表，以及网页上的公式（ChatGPT 等网页用的 KaTeX、维基百科的 MathML，会取出里面的 LaTeX 原文）。标题旁的 ¶、维基百科的 [编辑] 和引用编号这类页面装饰会被去掉。AI 复制按钮给的本来就是 Markdown，这时直接用纯文本；网页本来没什么格式、或者转换后明显少了内容时，也用纯文本，不会丢字。可以在设置里关掉
- **把文字拖进悬浮窗**：在网页、微信或任何应用里选中一段文字（也可以是 .md、.txt、.html、.rtf 这类文本文件，GBK 编码的 txt 也能读），拖到悬浮窗上，悬浮窗会分成上下两块：拖到**上半块「存成 Markdown」**就存成 md 文件（网页格式同样转成 Markdown，不动你的剪贴板）；拖到**下半块「放到剪贴板」**就只放进剪贴板、不存文件，⌘V 直接粘贴（网页格式也一起放进去，粘贴到支持格式的应用里能保留标题、列表）。拖进来的东西保存不了时，会按实际情况给出灰色提示：图片、其他文件，或者只带了应用内部数据的拖拽（比如新版微信左侧的会话，实测拖拽里只有一个 0 字节的 Qt 标记，任何应用都拿不到聊天内容）。悬浮窗贴边收起时，拖到那条细边上它会自己探出来。拖拽用的是单独的拖拽剪贴板，不会触发系统的粘贴询问
- **截图**：按 **⌃⌥A**，或点悬浮窗顶部的相机按钮。按下的那一刻整块屏幕会被「冻结」（画面不再变化，鼠标指针不会截进去），ClipMD 在上面盖一层自己的截图界面：
  - **自动认出窗口**：鼠标移到哪个窗口上，就自动选中这个窗口（菜单栏也算；在桌面上就是整块屏幕），选区外面变暗；点一下就选定。想要自己框，按住拖出一块区域
  - **分辨率**：选区左上角实时显示截出来的图片有多少像素（Retina 屏上是点数的 2 倍）
  - **放大镜**：选区时鼠标旁边有一个放大镜，把周围 17 × 11 个像素放大 10 倍，中间一格是鼠标正下方的像素；下面显示它的坐标（像素，从屏幕左上角算起）和颜色 `#RRGGBB`（换算成 sRGB，和网页里的颜色值一致）。按 **C** 复制色号，**⇧C** 复制 `rgb(…)`，复制后截图结束
  - **调整选区**：选好后拖动选区可以移动，拖边和角上的圆点可以改大小；右键回到重新选择（还没标注时）
  - **工具栏**（选区右下角）：矩形（R）、椭圆（O）、马赛克（M）、撤销（⌘Z）、识别文字（T）、钉在桌面（P）、丢弃 ✗（Esc）、完成 ✓（回车、⌘C 或双击选区）。选了矩形或椭圆后，第二行可以选 7 种颜色和 3 种粗细；马赛克可以选 3 种画笔粗细，涂到哪里哪里变成色块。画矩形、椭圆时按住 ⇧ 是正方形、圆。颜色和粗细会记住
  - **完成**：选区连同标注放进剪贴板（⌘V 就能粘贴），同时留在「剪贴板」记录里；屏幕上的焦点会还给原来的应用
- **钉在桌面**：截图工具栏里点图钉（或按 P），截图就浮在所有窗口上面，位置和截图时一样，方便对照着看。可以拖动；滚轮或双指捏合缩放（20%～500%，鼠标下的那一点不动）；双击、按 Esc 或点右上角的 × 关掉；右键可以复制图片、识别文字、恢复实际大小。可以同时钉好几张
- **识别文字（OCR）**：按 **⌃⌥O** 截图，选好区域（点一下窗口或框一块）就直接识别里面的文字；也可以按住悬浮窗顶部的相机按钮选「截图并识别文字」，或者在截图工具栏里点识别按钮（会连同标注一起识别）。已经在「剪贴板」记录里的图片，点右边的识别按钮，钉在桌面的图片右键也能识别。识别出的文字放进剪贴板，也作为一条文字记录留下来，需要时再一键存成 md。用的是系统自带的 Vision，完全在本机，不联网；支持简体、繁体中文和英文。识别按中文优先；结果里一个汉字都没有时（纯英文的图），再用自动识别语言认一遍，这样中英混排和纯英文都比较准。一般 0.3 秒左右就认完；超过 0.4 秒时屏幕顶部会显示「正在识别文字…」（第一次用时系统要准备识别模型，可能要十几秒）
- **自定义快捷键**：设置 →「快捷键」，点一下要改的那项，再按新的组合键（至少带 ⌘、⌃、⌥ 中的一个），按 Esc 取消。和另外两项重复、或者被别的应用占用时会提示，原来的快捷键保持不变；「恢复默认」改回 ⌃⌥S / ⌃⌥A / ⌃⌥O。菜单栏菜单里显示的快捷键会跟着变
- **按钮下面那行小字**：剪贴板里现在是什么（文字、网页文字、文件、空）。这里只看类型、不读内容，不会触发系统的粘贴询问
- **剪贴板记录**：悬浮窗的列表有两个标签「已保存 | 剪贴板」。复制过的文字和图片会先记在「剪贴板」里，不存成文件；文字可以点那一条右边的 ↓ 一键存成 md（网页格式同样会转），图片可以点识别按钮认出里面的文字；单击一行就把它放回剪贴板。列表平时露出 5 条，用滚轮或触控板可以翻看全部，点「展开」露出 10 条。点眼睛按钮（或右键「预览」）会在悬浮窗旁边弹出预览：文字可以切换「排版」（按 Markdown 显示，网页格式先转换，和存成 md 的结果一样）和「原文」，可以选中复制其中一段；图片显示大图，双击钉在桌面。预览下面有放回剪贴板、存成 md、识别文字、钉在桌面、在 Finder 中显示。按 Esc、点别的应用或再点一次眼睛按钮就关掉；同样的文字、同一张图再复制只是挪到最前面，不重复记；最多 50 条，单条超过 10 万字的文字、超过 30 MB 的图片不记；图片单独存成 PNG（放在记录文件旁边的 `images` 文件夹，同一张图只存一份），列表里的缩略图直接解出小尺寸，不把大图读进内存；密码管理器复制的内容、ClipMD 自己写进剪贴板的内容不记。记录保存在本机 `~/Library/Application Support/ClipMD/history.json`，删除和清空都可以撤销，设置里可以关掉。这个功能要求系统设成「始终允许」读取剪贴板
- **已保存**：列出最近 50 个文件，平时露出 5 条，用滚轮或触控板翻看其余的，点「展开」露出 10 条（两个标签共用展开状态）。两个标签叠在一起，悬浮窗的高度取两者中高的那个，切换标签时不变高变矮，内容左右滑动着淡入；条目少的那边下面会留白。单击一行就是复制这个文件；拖进聊天窗口或 Finder 是拷贝一份，原文件不动；拖到程序坞的废纸篓就是删除（可撤销）。右边三个按钮依次是预览、在 Finder 中显示、删除；右键一行有全部操作。在 Finder 里删掉或改名的文件，鼠标移进悬浮窗时列表会跟着更新
- **删除**：点垃圾桶会弹出两个选项。「从列表移除」只是不在悬浮窗里显示，文件还在；「移到废纸篓」会把文件放进废纸篓，可以从废纸篓找回。两种删除之后悬浮窗里都会出现「撤销」，大约 6 秒后消失
- **预览和编辑**：点眼睛按钮，默认打开 ClipMD 自己的窗口；也可以在设置里改成用 Typora、VS Code 等编辑器打开。窗口顶部可以切换三种模式：「预览」是排版好的只读视图，「编辑」是 Markdown 源码，「并排」左边改、右边实时显示效果（快捷键 ⌘1 / ⌘2 / ⌘3）。停止输入约 0.8 秒后自动保存，关窗口和退出时也会保存，文件的创建时间保持不变。工具栏有「复制文件」「在 Finder 中显示」，还有「打开方式」，临时换个编辑器打开
- **公式**：预览会渲染 `$…$`、`\(…\)` 行内公式和 `$$…$$`、`\[…\]` 独立公式（也支持写在列表、表格里的）。像「$5 和 $10」这种金额不会被当成公式，代码里的 `$` 也不处理。公式字体不随安装包带：第一次预览到有公式的文档时，顶部会提示「下载公式字体（约 0.8 MB）」，点了才下载；没下载时公式显示原文。写错的公式会显示原文并提示
- **移动**：按住顶部标题栏拖动。菜单栏图标的菜单或设置里打开「固定位置」，就固定在当前位置（不能拖、不会自动收起）。菜单栏里的「把悬浮窗移到」可以一键放到屏幕四个角
- **贴边收起**：点右上角的收起按钮，或者把窗口拖到屏幕边上。鼠标移到那条细边上会探出来，移开后缩回去
- **设置**：点悬浮窗右上角的齿轮，或者按 ⌘,：快捷键、外观（跟随系统 / 浅色 / 深色，悬浮窗、预览、截图界面一起换）、保存位置（比如改成 Obsidian 库）、预览方式（内置 / Typora / VS Code / 其他应用）、公式字体（下载或移除）、监听复制、固定位置和移到四角、读取剪贴板和录制屏幕的权限
- **图标**：应用图标是深色底板上的截图取景框加 Markdown 标志（M↓）。菜单栏里是同一个设计的单色版，跟着菜单栏的深浅自动变色；悬浮窗左上角是小号的彩色版，浅色模式下换成浅色底板，和浅色玻璃更协调
- **菜单栏图标**：保存、显示或隐藏悬浮窗、固定位置、贴边收起、打开设置
- **`clipmd://save`**：用快捷指令、Raycast 等工具运行 `open -g clipmd://save`，效果和按快捷键一样

## 系统权限

第一次保存时，macOS 可能会弹两次询问，都选允许：

1. **允许粘贴**：macOS 15.4 起，应用主动读取剪贴板内容前，系统都会先问一下。如果设置成了"每次询问"，悬浮窗里会提示，点「改成允许」会打开「隐私与安全性 → 粘贴」
2. **访问「文稿」文件夹**：默认存到 `~/Documents/ClipMD/`。如果拒绝了，可以到「隐私与安全性 → 文件与文件夹」里打开，或者在设置里换个保存位置

3. **屏幕录制**：第一次截图时会问。打开后要退出 ClipMD 再打开才生效（系统的规定）。没有这个权限时，悬浮窗里会提示，附一个按钮直接打开「隐私与安全性 → 录屏与系统录音」。截图用的是系统的 ScreenCaptureKit；macOS 可能隔一段时间提醒一次「ClipMD 正在访问你的屏幕」，选继续允许就行，所有截图工具都会这样

因为用的是本机临时签名，每次重新编译后，系统可能会再问一次。

文件默认存在 `~/Documents/ClipMD/`，按 `2026-10-24 标题.md` 命名：标题取第一个 Markdown 标题，没有就取第一行。密码管理器复制的内容（带 `org.nspasteboard.ConcealedType` 标记）会被跳过。

## 编译

只需要 Command Line Tools，不需要 Xcode：

```bash
./scripts/install.sh        # 编译、装进「应用程序」并打开（记录和设置在 ~/Library 里，重装不丢）
./scripts/build-app.sh      # 只生成 build/ClipMD.app
open build/ClipMD.app
./scripts/test.sh           # 单元测试
./scripts/make-icon.sh      # 重新生成应用图标 Resources/AppIcon.icns
```

想长期使用的话，把 `build/ClipMD.app` 拖进"应用程序"文件夹。

### 排查问题

每一次保存都会记日志：从哪触发（快捷键、按钮、菜单、URL）、剪贴板里是什么、成功还是失败。

```bash
/usr/bin/log show --last 10m --style compact --predicate 'subsystem == "dev.clipmd.ClipMD"'
```

（zsh 里有个同名的内建命令 `log`，所以要写全路径 `/usr/bin/log`。）

测试时可以加启动参数，不碰你的系统剪贴板和「文稿」文件夹：

```bash
open build/ClipMD.app --args -saveFolder /tmp/clipmd-test -pasteboardName dev.clipmd.test -historyFile /tmp/clipmd-history.json -enableTestURLs YES
```

加了 `-enableTestURLs YES` 之后，可以用 `open -g "clipmd://test/…"` 在不点鼠标的情况下走完整流程，比如 `drop?<文字>`、`drop-clipboard?<文字>`、`drop-file?<路径>`、`drop-html?<HTML 文件路径>`（模拟把文字拖进来松手）、`drop-target?save|clipboard|reject`、`snapshot-panel?<文件夹>`（悬浮窗截图）、`tab?clipboard`、`clip-save-latest`、`clip-copy?<序号>`、`clip-ocr-latest`（识别最近一张图片）、`shot?<图片>`（用一张图片假装是屏幕画面打开截图界面；不显示、不挡鼠标）、`shot-move?x,y`、`shot-down?x,y`、`shot-drag?x,y`、`shot-up?x,y`、`shot-key?c|C|esc|enter|cmd-z|r|o|m`、`shot-cmd?rect|ellipse|mosaic|color:<序号>|width:<序号>|undo|ocr|pin|confirm|cancel`、`shot-snapshot?<文件夹>`（截图界面和导出的图片各存一张）、`shot-pins`、`clip-preview?<序号>`（预览剪贴板记录里的一条；不显示、不挡鼠标）、`clip-preview-mode?plain|formatted`、`clip-preview-snapshot?<文件夹>`、`clip-preview-close`、`tab-click?saved|clipboard`（和点标签一样带动画）、`scroll-clips?<像素>`（给当前列表发一个滚轮事件）、`render-panel?<PNG 路径>`（把悬浮窗真实的图层树画下来，能看到滚动后的样子）、`preview-latest`、`mode?split`、`hide-latest`、`trash-latest`、`undo`、`close-previews`、`settings`、`install-fonts`、`snapshot?<文件夹>`（把预览内容画成浅色、深色两张 PNG）、`state`（把当前状态写进日志）。完整列表见 `Sources/ClipMD/TestURLs.swift`。不加这个参数时，这些命令不起作用。

## 性能

v0.10 在 macOS 27.0.1（Apple 芯片，2560 × 1440 的 Retina 屏）上的实测数据：

| 指标 | 数值 |
|---|---|
| 安装包大小 | 1.6 MB（不含公式字体，字体按需下载 0.8 MB） |
| 剪贴板记录 | 连续复制 40 段不同的文字全部记下，内存约 30 MB；不额外轮询，复用复制检测，写盘在后台、1 秒内没有新复制才写 |
| 连点检测的开销 | 闲置 30 秒内 CPU 时间约 0.05 秒（约 0.15%），开和关没有明显差别 |
| 启动后内存（phys_footprint） | 约 25 MB |
| 保存时的内存峰值 | 约 27 MB（间隔保存 3 次加快速连续保存 6 次） |
| 网页内容转 Markdown | 整页维基百科（573 KB HTML）从转换到写盘约 0.17 秒，在后台线程完成，内存只临时多约 10 MB |
| 打开预览窗口 | 约 44 MB；带 10 个公式的文档约 46 MB；并排模式约 49 MB |
| 预览窗口反复开关 10 次后 | 稳定在 48 MB 左右，不再上涨。关掉的窗口、文档、编辑器都已释放，多出来的是系统的文字排版缓存 |
| 截图时的内存 | 打开截图界面时约 140 MB（5120 × 2880 的整屏画面要 59 MB，Core Animation 显示时还要一份），关掉后回到 31 MB；连续截图 3 次后仍是 31 MB，截图界面的对象全部释放 |
| 剪贴板预览 | 打开图片预览时图片只解码到显示大小（最长边 1400 像素），关掉后放掉；连续预览图片 24 次后仍是 33 MB |
| 识别文字 | 一般 0.25～0.3 秒（含启动识别进程）；60 行中英混排的 4800 × 6600 大图约 1.7 秒。第一次用时系统要准备识别模型，约 15 秒，只有一次 |
| 识别文字后的内存 | 连续识别 4 次后仍是 25～26 MB。识别模型要占几十 MB，放在一个用完就退出的子进程里跑（就是 ClipMD 自己带上 `--ocr <图片>` 启动），子进程退出后内存还给系统；放在主程序里跑时，用过一次就会常驻 80 MB |
| 闲置 CPU | 0.0%～0.1% |

做法：

- 快捷键用 Carbon 的 `RegisterEventHotKey`，由系统直接派发，不需要全局监听键盘；在设置里录新快捷键时，先暂停全部快捷键，录完再注册回去
- 连点检测每 0.1 秒看一次剪贴板的变更计数，定时器允许系统合并唤醒，屏幕休眠时暂停；关掉这个功能后就完全不轮询。计数变了才看内容，而且只在系统设成「始终允许」时才看（否则每次复制都会弹询问）；内容只算一个哈希留在内存里，3 秒后丢掉
- 很多应用写剪贴板是「先清空、再写入」两步，如果刚好在中间看到空的剪贴板，会再看几次，等内容写进来再判断
- 每次剪贴板变化都会在日志里记一行：来源应用、和上次的间隔、内容类型（不记内容本身），方便排查某个应用连点无效的原因
- 同一个应用一次复制让计数一下子加 2 的，会落在同一次轮询里，只算一次；ClipMD 自己写剪贴板（保存后放上文件、复制代码块）也不算
- 文件读写、数字数都在后台线程完成；「已保存」只读最近 50 个文件，列表用 `LazyVStack`，只建露出来的几行
- 悬浮窗的高度跟着内容走：变高时立刻变高，变矮时等玻璃动画收完（0.5 秒）再缩；期间内容又变了就作废这次缩小，按最新量到的高度来（以前快速来回切换标签时，过期的缩小会把内容截掉）
- 悬浮窗的内容视图以左上角为原点：窗口改高度时顶边不动，里面的内容也不用重新定位。原点在左下角的话，窗口先变了大小、内容还没跟上的那一帧，整个面板会往下跳一下
- 没选中的标签不建真正的列表，只留一块算好高度的空白，免得藏在后面的行接到点击和滚轮
- 剪贴板预览：窗口只建一次，内容视图打开时新建、关掉时拆掉。图片用 Core Animation 图层显示（必须在 `updateLayer` 里设置图层内容，直接改的话视图一改大小 AppKit 就把图片清掉）；解码时关掉 ImageIO 的缓存，并且先在后台转成屏幕的色彩空间——实测显示时再转换的话，CoreGraphics 会把每次的转换结果留在它的色彩转换缓存里，预览一次多 6 MB，24 次涨到 110 MB
- 剪贴板列表用 `LazyVStack`，50 条里只建露出来的几行
- 列表不用系统滚动条（接了鼠标时系统会常驻一条带白色轨道的滚动条，压在玻璃上很突兀），换成一根 3 点宽的细条，只在滚动或鼠标移进列表时浮现、停下 1 秒后淡出；上下还有内容时那一边淡出一点。滚动位置放在单独的小对象里，滚动时只重画细条和渐隐，不让整个列表重新求值
- 截图界面全部用 Core Animation 图层：冻结的画面是一张图层，变暗是一个镂空的形状图层，鼠标移动时只改选区路径、放大镜的裁切和几行文字，不重画整块屏幕。放大镜直接从截图里裁出 17 × 11 个像素、放大时不插值；取色只读 1 个像素
- 马赛克：整屏先缩小成 8 点一格的色块图（只做一次），画笔的笔画当作遮罩露出色块；导出时用同样的色块和笔画重新合成，不经过屏幕显示，所以截出来的图和看到的一样清楚
- 窗口列表和截屏在后台同时进行；截图结束时窗口和冻结的画面一起释放，ClipMD 平时不常驻任何截图相关的东西。导出的 PNG 在后台编码；放进剪贴板的图片只放 PNG，别的应用要 TIFF 时才现场转换
- 保存提示的窗口只建一次，不显示时 `orderOut`，不参与屏幕合成
- "3 分钟前"这类相对时间只在鼠标移进悬浮窗时刷新，不靠定时器
- 鼠标进出用 AppKit 的 tracking area，悬浮窗不抢焦点（不能成为 key window）
- 预览用 Foundation 自带的 Markdown 解析器，再用 SwiftUI 原生排版，不嵌网页：不用另起网页进程，关窗口后对象全部释放。输入停止 150 毫秒后才在后台重新渲染，0.8 秒后才写盘
- HTML 用 Foundation 自带的 `XMLDocument`（HTML 整理模式）解析，不引入依赖；不用它的 XPath 查找后代，因为在整理过的 HTML 上 `.//code` 会找到别处的节点
- 公式用 SwiftMath 原生绘制成图片，按「公式 + 字号 + 深浅色」缓存，同一个公式只排版一次；没有公式的段落直接用 Text，不走公式的路径
- 图标切换（文件 → 对勾）用两个图标交叉缩放，不用 SF Symbols 的 `.contentTransition(.symbolEffect(.replace))`：实测后者在玻璃上每播一次，会临时多占约 50 MB 显存

测内存可以用 `footprint -p $(pgrep -x ClipMD)`，看 `phys_footprint_peak` 这一行。

## 公式

用 [SwiftMath](https://github.com/mgriebling/SwiftMath)（MIT）原生绘制，不嵌网页。源码放在 `Vendor/SwiftMath`，而不是用 SwiftPM 远程依赖，原因是 SwiftPM 生成的资源查找要求资源包放在 `.app` 根目录，签名过不了；改动都记在 `Vendor/SwiftMath/VENDOR.md`。

字体（Latin Modern Math，GUST Font License）不随安装包带。用户点「下载公式字体」后，从 SwiftMath 仓库 1.7.3 那次提交下载 3 个文件，逐个校验 SHA-256，全部通过才放到 `~/Library/Application Support/ClipMD/mathFonts.bundle`。
